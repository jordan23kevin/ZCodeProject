# Temu 价格申报视角批量处理 — 操作手册

> 子系统代码在 `lovart_bridge.py`（v2.5.0），页面 `order_price.html`，详细方法与踩坑见 `docs/order_price_automation.md`。
> 本技能是**操作速查 + 防坑清单**，不是代码细节。

## 0. 前置（必看）

- **先在 Edge 登录 Temu 卖家后台**，且 Edge 必须挂在**调试端口 9222**（用户数据目录 `C:\edge-cdp-profile`）。
- Bridge 已在跑（`http://127.0.0.1:8765`）。页面入口：`/order-price`（导航栏「📉 价格申报」）。
- **绝不另开第二个 Edge**：order_price 复用 `_ensure_edge_cdp` 连 9222，脚本自己不会开新浏览器。
- 核价底价字典 `ORDER_PRICE_FLOOR`（含意大利 115）在 `lovart_bridge.py` ~行 4164，纯数据配置。

## 1. 标准操作流程

1. **扫描预览**（只读，不点按钮）：点「🔍 扫描预览」或 `POST /api/order_price/scan`。
   - 返回 `接受/拒绝/跳过` 汇总 + 各站 `核价底价/接受最低价/拒绝最高价`。
   - **先核对**：确认当前页面数据与你的预期一致（Temu 列表是动态的，预览后到执行前数据可能变）。
2. **自动接受（≥底价）**：点「▶️ 自动执行」或 `POST /api/order_price/auto` → 拿 `task_id` → 轮询 `/api/order_price/status`。
   - 只点「调整」→ 弹窗「确认」；低于底价的保持原样（留人工）。
   - 每条通过会实时列出价格。
3. **批量拒绝（<底价）**：点「🗑️ 批量拒绝」或 `POST /api/order_price/reject` → 轮询 `status`。
   - 逐个勾选低价单（**绝不点全选**）→ 批量拒绝 → 填原因「价格过低」→ 点「拒绝」→ 最终弹窗点「拒绝」。
4. **拒绝后按 F5 刷新**再复核，否则看到的还是旧数据（Temu 不自动刷新）。

## 2. 防坑清单（血泪，改代码前先读 `docs/order_price_automation.md` 第 4 节）

| # | 坑 | 已固化的解决方案（勿回退） |
|---|----|--------------------------|
| 1 | 欧洲逗号小数 `€ 60,50` 被算成 6050 | 所有价格解析走 `_parse_price`（按逗号/点谁是小数位清洗） |
| 2 | 自动接受确认弹窗叠加死循环（堆 19 个） | `attempted` 集合：每订单只点一次「调整」；关不掉兜底点「取消」 |
| 3 | 拒绝原因填不进（React 受控组件） | 用 Playwright `textarea.fill("价格过低")` 真实输入，弃用「填首行+一键复制」 |
| 4 | 原因框计数虚高（空 22/33，实际 3） | `_op_reason_fields` 只收面板 `TB_innerRight` 内 textarea，不跨 `MDL_` |
| 5 | 面板内「拒绝」按钮点不到 | `_op_click_reject` 在 document 范围找可见「拒绝」（排除「批量拒绝」） |
| 6 | 最终弹窗是 `MDL_` 类，旧检测识别不到 | `_op_final_modal_present` 专门识别含「拒绝调价」的 `MDL_` 弹窗 |
| 7 | 最终弹窗提交按钮叫「拒绝」不是「确认」 | `_op_click_reject_final` 点「拒绝」（不是 `_op_confirm_modal` 的「确认」） |
| 8 | Temu 最终弹窗自动追加额外调价单 | 执行前核对追加项是否真低于底价；不该拒的在弹窗里点「移除」 |
| 9 | 拒绝后列表不刷新 | 处理完提示用户 **F5** 刷新再复核 |

## 3. 紧急处置

- **页面卡住一堆弹窗/面板**：直接 `F5` 刷新该标签页（未提交的拒绝不会丢数据，因为拒绝还没点）。
- **开工前已堆 >3 个确认弹窗**：代码会拒绝执行并提示先 F5 清除，照做即可。
- **想中止自动任务**：bridge 后台线程跑完当前页会停；若需硬停，重启 bridge（`lovart_bridge.bat --no-browser`）。
